# 推荐机制

播放模式切到「智能推荐」后，每一首都由推荐器挑选。代码在 `src/VupPlayer.Core/Recommend/Recommenders.cs`。

## 1. 候选从哪来

| 来源 | 说明 |
|---|---|
| 整个曲库（默认） | 所有未隐藏、未失效的曲目。设置里可以改成「只在当前列表里」。 |
| B 站发现池 | 后台按你常听的主播去 B 站搜「主播 歌回」「主播 翻唱」，过滤出像单曲的切片放进池子。推荐时按设置的比例（关闭 / 约 1/10 / 约 1/4）从池里挑，挑中后自动导入并播放，归到左侧「✨ B站发现」订阅源下。 |

发现池的过滤规则（`DiscoveryService.LooksLikeSong`）：时长 1–10 分钟；标题包含主播名或别名；标题里有「《」「唱」「歌」「翻唱」「cover」之一；不含「合集」「录播」「回放」「游戏」「名场面」等。启动 20 秒后检查一次，之后每 30 分钟检查；池子不够或超过 6 小时没刷新才真的去搜。被拒绝的候选不会再进池子。

## 2. 打分公式（weighted-v1）

```
分数 = 单曲喜好 × 喜欢 × 主播亲和 × 切片man亲和 × 冷却 × 同歌冷却 × 新鲜度 × 连续同主播 × 连贯性
```

**评分**：每条播放记录换算成一个 −1 到 1 的分数。听完（≥ 90%）记 +1，30 秒内手动切走记 −1，其余按听的比例线性映射（听一半约为 0）。

| 因子 | 计算 | 取值范围 | 作用 |
|---|---|---|---|
| 单曲喜好 | `exp(1.1 × pref)`，`pref = (评分和 + 主播平均 × 3) / (播放次数 + 3)` | 0.33 – 3.0 | 听完多的加分，老跳过的减分。次数少时往这个主播的平均水平拉，避免跳过一次就打入冷宫。 |
| 喜欢 | 标了喜欢 × 1.8 | 1 / 1.8 | |
| 主播亲和 | `exp(0.5 × a)`，`a = 主播所有曲目评分和 / (播放次数 + 5)` | 0.6 – 1.65 | 常听完的主播整体加分。 |
| 切片 man 亲和 | `exp(0.25 × a)`，平滑强度 8 | 0.78 – 1.28 | 影响比主播小。 |
| 冷却 | `1 − exp(−距上次播放小时数 / τ)`，`τ = 曲库曲目数 / 15`，限制在 1–72 小时 | 0.02 – 1 | 刚听过的压低，随时间恢复。300 首的曲库 τ ≈ 20 小时。 |
| 同歌冷却 | `1 − 0.8 × exp(−距同一首歌其他切片上次播放小时数 / τ)` | 0.2 – 1 | 避免两个人切的同一首歌挨着出现。按歌名判断，所以歌名准不准很重要。 |
| 新鲜度 | 没听过：`1.2 + 0.9 × exp(−导入天数 / 14)` | 1.2 – 2.1 | 新导入的切片有机会被播到。 |
| 连续同主播 | 最近 3 首里同主播 0/1/2/3 首 → 1 / 0.85 / 0.6 / 0.4 | | 避免一直是同一个人。 |
| 连贯性 | 上一首听完了且和它有相同标签 × 1.15 | 1 / 1.15 | 顺着刚才的风格走。依赖标签，可以让 Claude 帮忙打曲风、情绪标签。 |

**一定不推荐**：正在播放的这首，以及 12 小时内播过的最近 10 首（候选太少时自动放宽）。

**抽样**：不是总选最高分，而是按 `分数 ^ (1 / 温度)` 加权随机抽。设置里的「口味」就是温度：保守 0.6（集中在高分）、均衡 1.0、冒险 1.6（更平均）。

**发现池打分**：主播亲和（权重加倍）× 熟悉的切片 man 1.4 × 热度 `1 + log10(1 + 播放量) / 6` × 30 天内发布 1.3。

## 3. 推荐理由

每个因子带一句说明（例如「常听的主播 阿梓」「新导入，还没听过」「很久没听了」），乘数 ≥ 1.1 的取前三个，显示在「正在播放」下方。没有明显理由时显示「随机挑的」。

## 4. 怎么调

- **改参数**：`WeightedRecommender` 顶部的常量集中了所有权重，改完重新编译即可。
- **看效果**：设置 → 智能推荐 → 「看看接下来可能推荐什么」，或者在 Claude Code 里调用 `recommend_preview`，能看到每首的各个因子乘数。
- **比较算法**：每条播放记录都记了是谁选的（`play_events.recommender`：`weighted-v1`、`random`、`manual` 手动点播、`queue:*` 按队列顺序）。`get_recommender_stats` 给出各自的完播率和跳过率。可以把推荐算法临时切到「纯随机（对照组）」听一段时间做对比。

## 5. 接入自己的算法

1. 实现 `IRecommender`：输入 `RecommendContext`（候选、最近播放、当前曲目、是否允许 B 站发现），返回 `Recommendation`（曲目 id 或发现池条目、理由、分数、推荐器名）。
2. 需要数据就在构造函数里拿 `LibraryRepository`：`GetRecommendFeatures()` 给出每首的播放次数、评分和、上次播放时间等；`GetRecentPlays()`、`play_events` 表有完整明细。
3. 在 `RecommenderRegistry` 里加一行，设置菜单的「推荐算法」里就能切换。

## 6. 下一步可以做的

- 数据积累到几百条以后，用逻辑回归从播放记录里学权重（预测「会听完还是会跳过」），替换手调的常量。
- 时段因子：按小时统计每个主播 / 标签的完播率。
- 让 Claude 批量给曲目打曲风、情绪、语种标签，提升连贯性因子的效果。
- 离线回放评估：拿历史记录检验新公式，不用每次都靠听。
